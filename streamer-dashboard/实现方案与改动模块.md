# 线下主播看板 · 本轮实现方案与改动模块

> 针对用户 4 项需求（自动抓取与自动载入 / 清空并重新导入历史 + 导入Excel改造 / 部署上线 / 自动抓取流程）的实现说明。
> 用户本次新提供文件：`主播数据_2026-08-08 14_05_45.xlsx`（**区间导出**：统计时间 = `2026-08-01 ~ 2026-08-08 14:05:46`，1070 行、每房间号 1 行，累计 Aug1~Aug8）。

---

## 一、核心数据模型

| 概念 | 说明 | 去重键 |
|------|------|--------|
| **每日明细** | 单日文件（如 8.1-8.7，7474 行，每房 7 行） | `房间号::统计日期`（开始=结束） |
| **区间快照** | 区间文件（如本次新文件，1070 行，每房 1 行） | `房间号::开始~结束`（开始≠结束） |

- `parseStatTime()` 解析统计时间，区分单日 / 区间。
- `importRecords()` 按「房间号 + 统计日期/区间」去重覆盖：单日按天写入/覆盖；区间整体作为一条快照写入/覆盖，**不把汇总值错拆成多天**，避免重复计算。
- 前端 `records`（每日/区间全集）→ 派生 `streamers`（每房取「统计结束日期」最新一条）。

## 二、四项需求落地

### 1. 自动抓取与自动载入
- `server/fetcher.js` 抓取成功后 `syncToPublicDataset()` 把 `latest.json` 复制到 `public/streamer_data.json`（及 `dist/`，生产构建后保持一致）。
- 前端 `App.jsx` 的【同步数据】按钮 → `syncData()` → 重新拉取 `/streamer_data.json` 并覆盖本地缓存，看板自动刷新，无需人工点「载入看板」。

### 2. 清空并重新导入历史 + 导入Excel改造
- `src/utils/excel.js`（前端导入）：客户端用 `xlsx` 解析，已增强为**优先选择「主播数据」工作表**；解析结果经 `cleanRecord` 自动识别「统计时间」列，单日/区间分别按对应日期写入并去重。
- `server/index.js` 新增接口：
  - `POST /api/reimport-history`：清空服务器数据集后载入指定 xlsx（默认 8.1-8.7 每日明细，支持 `filePath` 覆盖）。
  - `POST /api/clear`：清空全部数据。
  - `POST /api/import`：清空并导入上传的 records。
- `SyncPage.jsx` 新增【数据管理】区：一键「清空并重新导入 8.1~8.7 历史」「仅清空本地记录」「清空全部数据」，均联动前端刷新。

### 3. 部署上线
- `npm run build` → `dist/`（已含 `streamer_data.json`，当前为 Aug1~Aug8 区间快照，1070 条）。
- 手机端适配：全站 Tailwind 响应式（`md:` 断点 + `viewport` meta），已就绪。
- 公网链接：本环境 CloudStudio 部署 API 持续 `fetch failed`（内网不可达，公网可达），**未拿到公网链接**。可用替代：
  - 本地服务 `http://localhost:8787`（已运行，含 SPA+API+自动抓取全功能）；
  - 同网段手机用 `http://<本机局域网IP>:8787` 实时查看；
  - 或将 `dist/` 手动拖到任意静态托管（Netlify / Vercel / GitHub Pages）获公网链接。

### 4. 自动抓取流程（截图红框）
- `fetcher.js` 严格按红框顺序模拟：
  1. 点【今日】或【昨日】（`selectors.todayTab/yesterdayTab`）；
  2. 点【下载】（`selectors.exportButton` 含「下载」）；
  3. 弹窗点【按日汇总下载】（`selectors.dailySummaryButton`）；
  4. `waitForDownloadFile('主播数据')` 轮询下载目录，等文件大小稳定（写完）后定位以「主播数据」开头的 .xlsx；
  5. 解析 → 合并进 `latest.json` → `syncToPublicDataset()` 自动同步看板；
  6. 失败重试（`maxRetry=2`），B站页面改版时可在 `server/config.json` 的 `selectors` 补充按钮文案，排查快照在 `server/logs/`。

## 三、涉及改动的模块（文件清单）

| 文件 | 改动 |
|------|------|
| `src/hooks/useStreamerData.js` | 区间记录 `统计日期` 改为截止日(as-of)；`streamers` 最新比较改为按「统计结束日期」优先（修复区间被单日覆盖）；`importRecords` 按房间号+日期/区间去重覆盖 |
| `src/components/Dashboard.jsx` | 新增【最新快照/每日明细】视图切换，默认按房间号取最新快照去重展示 |
| `src/components/SyncPage.jsx` | 新增【数据管理】区（重导历史/仅清空本地/清空全部），引入 `Trash2` 图标，联动 `onSync`/`onClearRecords`/`onClearAll` |
| `src/utils/excel.js` | 优先选择「主播数据」工作表（与服务器解析一致） |
| `server/parser.js` | `normalizeRow` 区间记录 `统计日期` 改为 `stat.end`（与前端一致） |
| `server/fetcher.js` | `export saveState()`；`waitForDownloadFile`、按日汇总下载流程、重试、自动同步 |
| `server/index.js` | 引入 `saveState`；新增 `writeDataset()`、`POST /api/import`、`/api/reimport-history`、`/api/clear` |
| `server/config.js` | `exportButton` 含「下载」；`dailySummaryButton` 含「按日汇总下载」 |
| `vite.config.js` | 加 `build.emptyOutDir:false`（规避沙箱 fs.rmSync trash 拦截导致构建失败） |
| `scripts/load_range.mjs` | 新增：复用 parser+config 把任意 xlsx 清空载入数据集 |

- 指标核对：1070 条主播总流水合计 = 157,559.40（与用户预期一致）；`大航海人数` 字段正确映射。
