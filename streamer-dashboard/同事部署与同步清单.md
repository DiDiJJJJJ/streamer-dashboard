## 一、项目技术栈与目录结构

### 1.1 技术栈

| 层 | 框架 / 语言 | 关键依赖 |
|---|---|---|
| 前端 | React 19 + Vite 8 + Tailwind CSS v4 | recharts v3（图表）、lucide-react（图标）、xlsx（Excel 解析）、@dnd-kit（拖拽）、date-fns |
| 后端 | Node.js（ESM，`"type":"module"`）+ Express 4 | node-cron（定时任务）、playwright-core（浏览器自动化）、cors、xlsx |
| 数据存储 | **无数据库**，全部为 JSON 文件 | `server/data/*.json` + `public/streamer_data.json` |
| 浏览器 | 本机需安装 Chrome / Edge | 由 `playwright-core` 驱动，用于登录 B 站后台并抓取数据 |
| 公网穿透 | Cloudflare Tunnel（`server/bin/cloudflared.exe`） | 也可改用 localtunnel / ngrok / 云服务器 Nginx |

- **版本要求**：Node.js ≥ 20（推荐 20 LTS 或 22）。本项目在本机用 Node 22 验证通过。
- **构建产物**：`npm run build` 生成 `dist/`，由后端 `server/index.js` 直接静态托管（前端 + 后端同源 :8787）。

### 2.3 配置文件与密钥位置

| 文件 | 作用 | 是否需提交/分发 |
|---|---|---|
| `server/config.json` | 用户配置（覆盖默认值）。**首次启动自动生成 `adminToken` 并写回此文件**；可覆盖 `cronToday`、`cronYesterday`、`chromePath` | 不提交（含密钥）；同事端首次启动会自生成 |
| `server/config.js` | 配置 schema + 默认值（端口 8787、B站 URL、选择器关键词、cron、超时）。一般无需改动 | 提交 |
| `vite.config.js` | 构建配置 | 提交 |
| `package.json`（两处） | 依赖与脚本 | 提交 |
| `.gitignore` | 已忽略 `node_modules`、`dist`、`server/data/`、`server/downloads/`、`.chrome-profile`、`logs`、`venv` | 提交 |

**密钥/凭证说明**：
- **没有第三方 API Key 文件**。B站 登录靠**本人扫码**，登录态保存在 `server/.chrome-profile/`（playwright 持久化上下文），扫码一次长期有效。
- **adminToken（管理员口令）**：用于写接口鉴权（`x-admin-token` 头）。**每个实例首次启动自动生成随机值并写入自己的 `server/config.json`**。⚠️ 不要把自己的 `config.json`（含 token）发给同事，同事端会自动生成独立 token。
- 若本机 Chrome/Edge 不在默认路径，需在 `server/config.json` 显式设置：
  ```json
  { "chromePath": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe" }
  ```

## 三、数据抓取与鉴权逻辑

### 3.1 整体流程

```
本人扫码登录 B站后台
   ↓（登录态持久化在 .chrome-profile，长期有效）
node-cron 定时触发
   ├─ 每 20 分钟        → 抓取【今日】  (cronToday)
   ├─ 每日 13:30        → 按日期精确补抓【昨日】早盘 (cronYesterday)
   └─ 每日 14:30        → 按日期精确补抓【昨日】终值覆盖 (cronYesterdayFinal)
   ↓
fetcher.js 打开数据页 → 点击「今日/昨日」→ 点「导出/按日汇总下载」
   ↓
解析 Excel (xlsx) → 聚合 → 写入 server/data/{today,yesterday,latest}.json
   ↓
同步到 public/streamer_data.json（看板前端数据源 → 触发 SSE 推送多端刷新）
```

### 3.2 鉴权（本人登录）

- 入口接口：`POST /api/login`（需 adminToken）。调用后由 `browser.js.openLoginWindow()` 打开**有头浏览器**跳到 B站 登录页（`https://passport.bilibili.com/login`），同事在弹出的浏览器窗口**扫码登录**即可。
- 登录态检测：`browser.js.checkLogin()` 通过 `api.bilibili.com/x/web-interface/nav` 判断 `isLogin`。
- 持久化：登录 cookie 存入 `server/.chrome-profile/`（launchPersistentContext），**无需重复扫码**。若 B站 会话失效，重新点一次「扫码登录」即可。
- 前端操作位置：页面顶部「数据自动同步」面板 →【扫码登录 B站】。

### 3.3 调度与补抓

- `server/index.js` 的 `setupCron()` 注册三条 node-cron 任务（时区 `Asia/Shanghai`）。
- **漏跑补偿（catch-up）**：服务在计划时刻未运行（关机/崩溃）时，`scheduler.js + startCatchUpWatchdog()` 会在**启动后 5 秒**及之后**每 10 分钟**回溯，自动补抓 36 小时内错过的任务，避免数据断档。

### 3.4 关键 API 一览（后端 `server/index.js`）

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `GET /api/version` | 否 | 返回版本号（前端徽章比对用） |
| `GET /api/status` | 否 | 登录状态、上次抓取时间 |
| `GET /api/data`、`GET /api/roster` | 否 | 看板数据 / 名册（分享链接他人也可读） |
| `GET /api/events` | 否 | SSE 实时推送（数据变更即广播） |
| `POST /api/login`、`/login/done` | 是 | 打开/确认扫码登录 |
| `POST /api/fetch`、`/fetch-date`、`/catchup` | 是 | 手动触发抓取/补跑 |
| `POST /api/roster`、`/import`、`/rollback` | 是 | 名册维护与回滚 |
| `POST /api/config` | 是 | 修改运行配置 |
| 写接口通用规则 | `x-admin-token` 头必须等于 `server/config.json` 的 `adminToken`，否则 401 |  |

## 四、部署方式

### 4.1 本地运行（最简）

```bash
# 1) 安装依赖（两处）
npm install --registry=https://registry.npmmirror.com
cd server && npm install --registry=https://registry.npmmirror.com && cd ..

# 2) 构建前端（生成 dist/，并写入 version.json）
npm run build

# 3) 启动服务（自动托管前端 + API，监听 8787）
cd server
node index.js
# 或双击 server\启动数据同步服务.bat（含首次依赖安装）
```

- 浏览器打开 `http://localhost:8787` →「数据自动同步」→【扫码登录 B站】→ 等待自动抓取。
- 数据抓取成功后 `public/streamer_data.json` 生成，看板即可正常显示。

### 4.2 防掉线（推荐：看门狗）

服务进程偶发崩溃会导致公网 502。**根目录 `启动主播管理后台服务-自动重启.bat`** 是看门狗循环（崩溃 5 秒自启），生产环境建议用它而非直接 `node index.js`。

### 4.3 远程 / 公网部署

- **方案 A（Cloudflare Tunnel，免费固定子域）**：`server\run_tunnel.bat` 调用 `bin/cloudflared.exe tunnel --url http://localhost:8787`，得到 `*.trycloudflare.com` 临时公网地址（重启会变）。要固定域名需注册 Cloudflare 并绑定。
- **方案 B（云服务器 + Nginx）**：把 `streamer-dashboard` 上传到云主机（Win/Linux 均可），装好 Chrome/Edge 并配置 `chromePath`，运行 `node server/index.js`，Nginx 反代 8787 → 80/443。
- **方案 C（localtunnel）**：`npm run tunnel`（临时公网，每次地址变化）。

> 无论哪种，前端都已由后端同源托管，**无需单独部署静态站**。

### 4.4 是否需要数据库初始化

**不需要。** 本项目无数据库，数据以 JSON 文件形式在首次抓取后自动生成于 `server/data/`。唯一需要"准备"的是：
- 本机有 Chrome/Edge（用于抓取）；
- 本人扫码登录 B站（用于获取数据源）；
- 若需沿用既有「策展名册」（`roster.json`），应单独把 `server/data/roster.json` 拷贝过去（该目录被 git 忽略，不会随仓库走）。

### 4.5 部署前置检查清单

- [ ] Node.js ≥ 20 已安装（`node -v`）
- [ ] 两处 `npm install` 已完成
- [ ] `npm run build` 成功（出现 `dist/`）
- [ ] 本机 Chrome/Edge 存在（`config.js` 能自动探测，否则手动设 `chromePath`）
- [ ] 防火墙放行 8787（若远程访问）
- [ ] 已用看门狗/后台方式启动，避免窗口关闭即停服

## 五、版本迭代与同步

### 5.1 版本号机制

- 唯一来源：`package.json` 的 `version` 字段（当前 `1.0.0`）。
- `npm run build` 会先执行 `scripts/write-version.mjs`，读取 `package.json.version`，连同 git commit 写入：
  - `public/version.json`（开发/构建产物）
  - `dist/version.json`（生产）
  - 并通过 `GET /api/version` 暴露。
- 前端 Header 右上角显示版本徽章：**灰色=前后端一致；黄色=检测到服务端版本与前端不一致（需刷新）**。

### 5.2 发布新版本的本地步骤

```bash
# 1) 修改 package.json 的 version（如 1.0.0 → 1.1.0）
# 2) 重新构建
npm run build
# 3) 重启服务（用看门狗 bat 则重开即可，会从新 package.json 读版本）
# 4) 浏览器强刷（Ctrl+Shift+R），徽章应显示新版本
```

### 5.3 如何同步给同事

本项目当前为**本地 git 仓库、未配置 remote**。两种同步方式任选：

**方式 A：Git 仓库同步（推荐长期协作）**
1. 在 GitHub / Gitee 新建空仓库，本地 `git remote add origin <url>` 并 `git push`。
2. 同事：`git clone <url> && cd streamer-dashboard`。
3. 同事按第四章安装依赖、构建、运行。
4. 后续更新：你 `git commit && git push`；同事 `git pull` 后 `npm run build` 重启。
   > 注意 `.gitignore` 已排除 `node_modules`、`dist`、`server/data/`、`.chrome-profile`、`logs`、`venv`，因此仓库体积很小、且**不含任何密钥/运行时数据**。

**方式 B：打包分发（无 git/一次性）**
- 打包应包含：`src/`、`server/`（源码，不含 `server/data`、`.chrome-profile`、`downloads`、`logs`）、`public/`（可不含 `streamer_data.json`）、`scripts/`、`package.json`、`package-lock.json`、`vite.config.js`、`index.html`、`share.html`、`server/bin/cloudflared.exe`、`server/config.example.json`。
- **排除**：`node_modules/`、`dist/`、`server/node_modules/`、`server/data/`、`server/downloads/`、`server/logs/`、`.chrome-profile/`、`*.log`、`venv/`。
- 同事解压后执行两处 `npm install` + `npm run build` + 启动。
- 若需交接既有名册，单独把 `server/data/roster.json` 发给同事放入其 `server/data/`。

> ⚠️ **永远不要**把 `server/config.json`（含 adminToken）或 `.chrome-profile/`（含你的 B站 登录态）发给他人。

## 七、常见问题（快速定位）

- **页面报「数据加载失败：HTTP 502」**：本地 8787 没起来（服务进程掉了）。用根目录看门狗 bat 重启；确认 `curl http://localhost:8787` 返回 200。
- **看板空白/无数据**：还没扫码登录或登录失效 → 重新「扫码登录 B站」；等待自动抓取（每 20 分钟，或点手动抓取）。
- **版本徽章变黄**：前端与后端版本不一致 → 强刷浏览器（Ctrl+Shift+R）；若仍不一致，确认服务已用最新 `dist` 重启。
- **抓取报 EPERM**：旧版本写入固定文件名所致；当前源码已改用唯一时间戳文件名，重新 `npm run build` 并重启即可根治。
- **找不到浏览器**：在 `server/config.json` 设 `chromePath` 指向本机 Chrome/Edge。
