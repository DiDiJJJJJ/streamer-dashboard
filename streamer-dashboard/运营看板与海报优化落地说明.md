## 一、完整页面布局方案（运营数据看板）

页面保持四段式骨架，新增「团队KPI完成率」独立模块，整体分区如下（桌面端自上而下，移动端单列堆叠）：

| 分区 | 内容 | 关键变化 |
|------|------|----------|
| **ZONE 1 概览条**（sticky 常驻） | 本月线上线下总流水 / 本月线下总流水 / 线下主播数 / 运营经纪人（线下） | 首卡由「团队KPI完成率（人数口径）」改为「本月线上线下总流水」，与新模块分工 |
| **ZONE 1.5 团队KPI完成率**（新增） | 两张环形进度：**线上线下总流水完成率**、**线下总流水完成率**，各带实际/目标 | 需求②核心交付；数据来自卡片管理「已显示」运营 |
| **ZONE 2 结构分析** | 占比环形图 ↔ 横向条形图切换 + 排序图例 | 修复条形图昵称截断 |
| **ZONE 3 明细数据** | 经纪人聚合表（排名/主播数/流水/天数/时长/TOP3） | 联动高亮 |
| **ZONE 4 目标进度** | 个人KPI卡（显隐/拖序/排序） | 移除原顶部团队汇总条（已由 ZONE1.5 承担） |

**响应式断点**：概览条 `grid-cols-2 → lg:grid-cols-4`；KPI卡 `grid-cols-1 → md:grid-cols-2 → xl:grid-cols-3`；环形模块 `grid-cols-1 → sm:grid-cols-2`。

```

├─ useCountUp / CountUp            # 数字滚动动画 hook + 展示组件

├─ DashboardSkeleton               # 首屏微光骨架（加载动画）

share.jsx                          # 对外分享页（需求④公开端）
└─ <PosterButton board={b} />      # 底部「保存榜单海报」按钮

ChallengePoster.jsx  (新增，可复用) # 生成按钮 + 预览弹窗 + 下载
└─ 动态 import('../utils/poster')  # 海报绘制逻辑独立分包（懒加载，不拖累首屏）

├─ loadImage(src)                  # 同源图片加载（/logo.jpg、/ziluo-avatar.png），失败优雅降级
```

**依赖策略**：海报采用原生 Canvas 绘制（非 html2canvas），原因——无跨域污染（`toDataURL` 可用）、像素可控、零新增依赖、构建体积更小（poster 分包仅 5.76KB）。

## 三、动效设计要点（需求③）

统一沿用已有 `fx-*` 动效系统（仅过渡 GPU 友好属性，避免数据密集表格抖动），本轮新增三类：

1. **入场 stagger（`fx-enter` + `animationDelay`）**：ZONE1→ZONE1.5→ZONE2→ZONE3→ZONE4 依次 0/80/160/240/320ms 上浮淡入（`@keyframes fx-fade-up`）。
2. **加载动画（`fx-skeleton` + `fx-shimmer`）**：首屏 280ms 微光骨架（4 张概览卡 + 两块面板 + 6 张 KPI 卡），随后内容入场，营造数据载入过渡。
3. **数据过渡**：
   - 关键数字 `CountUp` 缓动滚动（cubic 三次缓出，~900ms）；
   - 环形进度 `stroke-dashoffset` 1s 缓动绘制（`.fx-ring-progress`）；
   - 饼图/条形图 `animationDuration=700` 统一节奏；
   - KPI 进度条 `transition-all`、表格行 hover 内嵌强调条（沿用）。
4. **无障碍**：`prefers-reduced-motion` 下关闭位移/动画，保留可用性。

## 四、条形图昵称截断修复（需求①）

- 根因：`<YAxis width={72}>` 固定宽度过窄，长运营昵称被裁剪/溢出。
- 修复：
  - `yAxisW = clamp(64, maxNameLen*11+18, 180)` 按最长昵称动态计算；
  - `interval={0}` 显示全部刻度；`tickFormatter={(v)=>v}` 输出完整昵称；
  - 条形模式容器高度提升为 `h-[440px] lg:h-[480px]`，避免拥挤；
  - 图例昵称去掉 `truncate`，改为 `break-words` + `title` 悬浮全名。
- 效果：任意长度昵称完整展示，不再省略或溢出。

## 五、团队KPI完成率模块重构（需求②）

- **数据口径**：取「卡片管理」中**未隐藏（已显示）**的全部运营，汇总其 KPI 目标（totalKpi / offlineKpi）与最新实际流水（allRevenue / offlineRevenue，当月口径），计算两项完成率：
  - `线上线下总流水完成率 = Σ实际(总) / Σ目标(总)`
  - `线下总流水完成率 = Σ实际(线下) / Σ目标(线下)`
- **排版**：两张并排环形进度（蓝=线上线下、琥珀=线下），中心显示百分比（count-up），下方「实际 / 目标」金额；模块标题标注「已选 N 位运营」，随卡片显隐实时刷新。
- **联动**：在 ZONE4「卡片管理」中隐藏某运营 → 其目标/实际立即从团队完成率中剔除，环形重绘。

## 六、挑战赛海报生成分享（需求④）

**触发位置**：运营端赛事页顶部「生成海报」按钮；对外分享页（`/share.html`）底部「保存榜单海报」按钮（同一 `PosterButton` 组件）。

**海报视觉设计（720×1280 竖版，@2x  retina）**：
- 背景：品牌蓝垂直渐变 + 两枚半透明装饰光斑；
- 顶部：左侧 `logo.jpg`（公会 logo）＋「紫萝传媒」字样；右上角圆形裁剪的**拳击紫小萝虚拟形象**（白描边发光环）；
- 标题：「2026 暑期主播挑战赛 · 本周榜单 · 数据战报」＋统计周期；
- 三栏汇总卡：参赛人数 / 达标人数 / 总流水；
- TOP3 领奖台：金/银/铜奖牌 + 昵称 + 流水 + 赛道；
- 完整榜单 TOP（剩余最多 11 条）：排名 + 赛道标签（排位赛=琥珀/晋级赛=蓝）+ 昵称（超长省略号）+ 右对齐流水；
- **数据统计时间**：页脚上排居中显示；
- **底部小字**：「【活动最终解释权归紫萝传媒所有】」；
- **不含赛制文字**（按要求刻意省略）。

**交互**：点击 → 客户端 Canvas 绘制 → 弹窗预览 → 「下载/保存图片」（PNG，手机端可长按保存）。图片资源同源加载，无跨域污染。
