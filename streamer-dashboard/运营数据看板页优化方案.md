# 运营数据看板页优化方案

> 适用页面：`src/components/AgentDashboard.jsx`（运营数据看板 / 运营经纪人维度）
> 配套组件：`Dashboard.jsx`（主播汇总）、`QuickDateFilter.jsx`（日期筛选）、`Money.jsx`
> 目标：解决「UI 排版散、饼图可视化弱、KPI 指标排列体验差」三类问题，统一为「概览 → 结构 → 明细 → 目标」四段式信息架构。

---

## 一、现状诊断（基于当前代码事实）

### 1.1 当前页面结构（自上而下）
| 区块 | 代码位置 | 实现方式 | 主要问题 |
|------|----------|----------|----------|
| 顶部概览卡 ×3 | AgentDashboard L219-232 | `grid-cols-1 sm:grid-cols-3`，渐变背景 | 指标命名易混淆（"运营经纪人总数"实为线下子集）；与底部 KPI 区存在口径重复 |
| 饼图 + 排行图例 | AgentDashboard L235-293 | 左饼图 `h-72` + 右图例列表，`lg:grid-cols-2` | 扇区上直接渲染 `label={entry.agent}`（L260），分类多时标签严重重叠；`activeIndex` 默认 0（L75），首扇区永远"弹出"；tooltip 仅显示金额无占比 |
| 线下主播数据情况 | AgentDashboard L296-350 | 表格 `min-w-[760px]` + 展开 TOP3 | 与饼图同源（均按运营经纪人聚合），但两块分离；窄屏强制横向滚动 |
| 本月 KPI 完成进度 | AgentDashboard L353-409 | 每经纪人双 KPI 卡，`md:grid-cols-2 xl:grid-cols-3` | 卡片不可隐藏/排序；无团队汇总条；卡片内层级（标签/实际值/进度/百分比）偏挤 |

### 1.2 饼图核心问题（重点）
- **标签重叠**：`label={(entry) => entry.agent}` 把经纪人名写在扇区内（L260）。当前调色板 12 色，若存在 8+ 经纪人，小扇区标签互相压字，移动端完全不可读。
- **首扇区常驻高亮**：`activeIndex` 初始值为 `0`（L75），`renderActiveShape` 把第 1 个扇区外扩 10px + 描边环（L45-59），加载即"假 hover"。
- **配色可辨识度一般**：`PIE_COLORS`（L12-16）混入了相近明度色（如 `#2563eb` 蓝与 `#06b6d4` 青、`#22c55e` 绿与 `#10b981` 翠），相邻扇区易误读。
- **tooltip 信息不足**：`formatter={(v) => <Money value={v} />}`（L267）只有金额，缺占比与排名。
- **长尾无收敛**：无"其他"合并桶，6~12 个经纪人时小扇区成为视觉噪声。

### 1.3 KPI 核心问题
- **不能显隐/排序**：`kpiList` 排序固定为 `max(totalProgress, offlineProgress)` 降序（L188），用户无法按"线下总流水"或"达标状态"重排，也无法隐藏某经纪人卡。
- **无团队层汇总**：只呈现"已完成 X / Y 人"（L361），缺「团队整体 KPI 完成率」「总目标 vs 实际」的宏观进度。
- **卡片信息密度高但层级不清**：标签、KPI 输入框、进度条、实际值、百分比挤在 ~140px 卡内（L414-441），视觉动线混乱。

## 二、页面结构重构

### 2.1 信息分区（四段式）
将现有 4 块重组为清晰层级，每块有独立 `SectionHeader`（标题 + 副标 + 操作区）：

```
┌─────────────────────────────────────────────────────────┐
│ ZONE 1  概览条（团队级 KPI 汇总 + 关键计数，sticky 顶部）  │
├─────────────────────────────────────────────────────────┤
│ ZONE 2  结构分析（占比环形图 + 横向条形切换 + 排序图例）   │
├─────────────────────────────────────────────────────────┤
│ ZONE 3  明细数据（经纪人聚合表，可排序/搜索/展开 TOP3）   │
├─────────────────────────────────────────────────────────┤
│ ZONE 4  目标进度（个人 KPI 卡，支持显隐/拖拽排序）        │
└─────────────────────────────────────────────────────────┘
```

- **ZONE 1 概览条**：把"团队 KPI 完成率""本月线下总流水""线下主播数""运营经纪人（线下）数"合并为一条 4 列紧凑概览，替代原散落的 3 张渐变卡。渐变背景改为**扁平白卡 + 主色数字**，符合现有 `fx-panel` 体系，避免视觉过重。
- **ZONE 2 / ZONE 3 关联**：饼图与明细表都按"运营经纪人"聚合，可在 ZONE 2 图例点击某经纪人 → ZONE 3 表格自动滚动/高亮该行（联动）。
- **ZONE 4 独立**：KPI 个人卡与明细表解耦，避免重复横向滚动。

### 2.2 栅格与响应式
统一采用 12 列栅格（Tailwind `grid-cols-12`），断点遵循：

| 视口 | 断点 | 布局要点 |
|------|------|----------|
| 桌面 | `≥1280px (xl)` | ZONE1 四列；ZONE2 图表(7) + 图例(5)；ZONE3/ZONE4 全宽 |
| 平板 | `768–1279px (md~lg)` | ZONE1 两列(2×2)；ZONE2 图表/图例上下堆叠；ZONE4 两列 |
| 移动 | `<768px (base)` | 全部单列堆叠；图表高度降到 `h-56`；表格保持横向滚动但加"关键列优先"；KPI 卡单列 |

**关键改动点**：
- 饼图容器：`h-72 lg:h-80`，移动端 `h-56`，避免大留白。
- 明细表：保留 `overflow-x-auto`，但给主列（经纪人/总流水）`position: sticky; left:0` 背景白，提升窄屏可读性。
- 概览条在 `<768` 用 `grid-cols-2`，数字降级为 `text-xl`。

### 2.3 视觉层级与间距规范
- 区块间距统一 `space-y-4`（已用），区块内 padding `p-4`。
- 标题：`text-sm font-semibold text-text` + 左侧 16px 图标（沿用 `PieIcon/Users/Target`）。
- 卡片圆角 `--border-radius-lg (12px)`，边框 `border-border`，背景白，无渐变。
- 交互态：hover 用 `hover:bg-bg`，卡片微动 `fx-lift`（已存在）保持。

## 三、图表样式升级

### 3.1 环形图（饼图）修复清单
| 项 | 现状 | 优化 |
|----|------|------|
| 标签 | 扇区内 `entry.agent`（重叠） | **移除扇区标签**，仅保留图例；扇区 hover 时 tooltip 显示「经纪人 + 金额 + 占比 + 排名」 |
| 配色 | 12 色混明度 | 改用**按色相均匀分布的 12 色板**（见 §3.4），相邻扇区色相差 ≥30° |
| 长尾 | 无收敛 | 占比 < 3% 的经纪人合并为「其他」扇区（最后计算），保证主视觉清晰 |
| 默认高亮 | `activeIndex=0` 常驻弹出 | 默认 `activeIndex=null`，仅真实 hover 时放大；移出恢复 |
| tooltip | 仅金额 | `formatter` 返回 `金额 + 占比% + 排名第 N` |
| 图例 | 静态列表 | 可点击过滤（点图例→表格联动高亮）；显示「金额 + 占比」；按金额降序 |
| 类型切换 | 无 | 提供「环形 / 横向条形」切换（见 §3.2） |

### 3.2 是否替换图表类型评估
- **保留环形图作为"占比"视图**：适合回答"各经纪人贡献结构占比"，但需按 §3.1 修复。
- **新增横向条形图（推荐用于精确对比）**：当分类 > 5 时，条形图在「数值精确比较 / 排名」上优于饼图（人眼对长度比对角度更敏感）。用 recharts `<BarChart layout="vertical">`，按金额降序，柱尾标注金额。
- **结论**：**不删除饼图，增加「环形 ↔ 条形」一键切换**，默认按数据量自适应（≤5 类默认环形，>5 类默认条形），用户可手动切。
- 不推荐：纯饼图做排名、3D 饼图（扭曲角度）、雷达图（维度不匹配）。

### 3.3 交互增强
- 图例 ↔ 饼图 ↔ 明细表 三向联动高亮（hover 图例 → 饼区高亮 + 表格对应行底色）。
- 环形中心显示「总流水」+「经纪人数量」聚合文字（donut center label），替代首扇区假高亮。
- 切换图表类型时保留当前 hover/选中状态。

### 3.4 推荐调色板（12 色，色相均匀）
```
#2563EB 蓝   #0EA5E9 天蓝  #06B6D4 青   #10B981 绿   #84CC16 黄绿
#F59E0B 橙   #EF4444 红   #EC4899 粉   #8B5CF6 紫   #6366F1 靛
#14B8A6 蓝绿 #A855F7 品紫
```
较原 `PIE_COLORS` 提升：移除明度相近对，按 HSL 色相环均布，保证相邻差异明显，且均满足白字/深字对比度 AA。

## 四、KPI 改进

### 4.1 指标优先级与排序
- 每经纪人维持双 KPI：**线上线下总流水**（`totalKpi`）、**线下总流水**（`offlineKpi`），口径沿用现有（AgentDashboard L166-188）。
- ZONE 4 顶部新增**排序工具栏**：下拉选择「按总流水 / 按线下流水 / 按达标状态 / 按完成率」，升降序切换。
- 新增**团队汇总条**（置于 ZONE 1 或 ZONE 4 顶部）：团队总目标 = Σ各经纪人 KPI；团队实际 = Σ各经纪人实际；展示整体完成率进度条 + "已达标 X/Y 人"。

### 4.2 自定义显隐与排序（用户可控）
- 新增「卡片管理」弹层（齿轮图标）：
  - **显隐**：勾选框控制哪些经纪人卡显示（如临时隐藏低效经纪人）。
  - **拖拽排序**：列表内拖拽调整卡片顺序（HTML5 drag 或 `@dnd-kit` 轻量方案；若不想加依赖，可用上移/下移按钮）。
- 状态持久化：`localStorage` key 复用现有 `agent_kpi_map_v2` 结构，新增 `hidden: string[]` 与 `order: string[]` 字段；与 KPI 数值同写同读（沿用 `updateKpi` 模式，新增 `updateLayout`）。
- 默认 `order=[]` 时按完成率降序（兼容现状）。

### 4.3 卡片内信息层级与视觉规范
单卡重排为三层，自上而下：
```
[ 经纪人名 .................... 状态徽标(已完成/未完成) ]
[ 指标A标签       KPI输入框 ]
[ ▓▓▓▓▓▓▓░░░ 实际值 ¥X  ·  完成率 Y% ]
[ 指标B标签       KPI输入框 ]
[ ▓▓▓▓▓▓▓░░░ 实际值 ¥X  ·  完成率 Y% ]
[ 名下主播 N 人（线下 M 人）· 修改即保存 ]
```
- 进度条达标用 `bg-success`，未达标用主色（沿用 `KpiBar` 逻辑 L430-435）。
- 实际值与百分比同行右对齐，避免数字与标签错行。
- 卡片最小高度统一，避免列表参差。

### 4.4 顶部团队汇总条（新增，团队层）
- 4 列：`团队 KPI 完成率` `本月线下总流水` `线下主播数` `运营经纪人(线下)`。
- `团队 KPI 完成率` = 达标人数 / 总人數，配一个细进度环或条。
- 该条在 `<768` 折叠为 2×2，`sticky top-0` 便于长页滚动时始终可见关键数。

## 五、实施建议

### 5.1 改动文件与函数
| 文件 | 改动 |
|------|------|
| `src/components/AgentDashboard.jsx` | ① 新增 `SectionHeader` 组件；② 重构顶部为 ZONE1 概览条 + 团队汇总；③ 饼图组件 `PiePanel`：移除扇区 label、加 `computeOthers()` 长尾合并、`activeIndex` 默认 null、tooltip 含占比/排名、`renderActiveShape` 仅真实 hover 触发；④ 新增 `ChartTypeToggle`（环形/条形）；⑤ 图例点击联动表格高亮；⑥ KPI 区加排序工具栏 + 显隐/拖拽面板 + `updateLayout` 持久化 |
| `src/components/AgentDashboard.jsx` 调色板 | `PIE_COLORS` 替换为 §3.4 的 12 色 |
| `src/hooks/useStreamerData.js` / `utils` | 如需服务端聚合可下沉，但当前前端聚合已满足，暂不改 |
| `index.css` | 新增 `.kpi-card` / `.legend-item` 等少量类（可选，亦可全用 Tailwind） |

### 5.2 实施顺序（建议）
1. **先修图表**（§3）：改动小、收益高、风险低 → 解决最痛的"饼图看不清"。
2. **再理结构**（§2）：四段式分区 + 概览条，提升整体排版。
3. **后做 KPI 自定义**（§4）：显隐/排序涉及 localStorage 结构扩展，放最后，且需保持向后兼容（旧 `agent_kpi_map_v2` 无 `order/hidden` 字段时降级为默认）。

### 5.3 风险与回归
- **向后兼容**：`agent_kpi_map_v2` 增加 `order/hidden` 字段需 `?? []` 兜底，旧用户无感。
- **性能**：经纪人数量通常 < 30，前端聚合与渲染无压力；条形图用 `layout="vertical"` 时 y 轴类目多需限制高度 + 滚动。
- **联动复杂度**：图例→表格高亮用 `setActiveAgent` 状态跨 ZONE 传递，注意避免与现有 `expanded` Set 冲突（可新增独立 state，不改 `expanded`）。

### 5.4 验证清单
- [ ] 移动端 `<768`：四区单列、图表 `h-56`、表格主列 sticky、KPI 卡单列。
- [ ] 饼图：无标签重叠；hover 首扇区不再常驻弹出；tooltip 显示金额+占比+排名。
- [ ] 图表切换：环形 ↔ 条形数据一致；>5 类默认条形。
- [ ] KPI：可排序、可隐藏、可拖序；刷新后布局保留；旧 localStorage 不报错。
- [ ] 团队汇总条：完成率 = 达标/总人數，数字正确。

## 七、落地补充（构建产物清理 + 交互修正）

> 原 §4.2 提出的「拖拽排序」与构建产物清理，在落地时做了如下修正与补充，使方案完整且一致。

### 7.1 KPI 排序：上移/下移 → 真拖拽（@dnd-kit）
- 原方案允许「HTML5 drag 或 @dnd-kit；若不想加依赖可用上移/下移」。实际落地采用 **@dnd-kit**（`@dnd-kit/core` + `@dnd-kit/sortable` + `@dnd-kit/utilities`，依赖见 `package.json`），实现真正的指针/键盘拖拽。
- 实现：`DndContext` + `SortableContext(verticalListSortingStrategy)` 包裹「卡片管理」列表；每行 `SortableAgentRow` 用 `useSortable({ id: agent })` 绑定手柄（`GripVertical`），`PointerSensor`(distance:4 防误触) + `KeyboardSensor` 支持无障碍；`handleDragEnd` 用 `arrayMove` 重排 `order` 数组并 `updateLayout` 持久化。
- 「卡片管理」面板文案更新为「显隐 + 拖拽排序」：勾选框控制显隐、手柄拖拽改顺序、一键「重置为默认顺序与全显」。

### 7.2 构建产物清理（消除 dist 残留旧块）
- **问题**：`vite` 的 `emptyOutDir` 会逐文件调用 `fs.rmSync`，而本构建环境对 `fs.rmSync` 做了 `safe-delete`（trash）拦截，`dist/.nojekyll` 等触发 trash 报错导致**构建直接失败**（已实证）。
- **修复**：`vite.config.js` 维持 `emptyOutDir:false`；新增 `scripts/clean-dist.mjs`，在 `vite build` 之前用 **PowerShell `Remove-Item -Recurse -Force`（走回收站，本环境稳定可用）** 整体清空 `dist`，旧产物移入回收站而不留在 `dist`。`package.json` 的 `build` 脚本改为 `node scripts/write-version.mjs && node scripts/clean-dist.mjs && vite build`。
- **效果**：每次构建后 `dist/assets` 仅含本次产出的哈希文件，不再累积历史 `main-*.js` / `index-*.js`。

### 7.3 体积告警消除（vendor 分包）
- `vite.config.js` 新增 `build.chunkSizeWarningLimit: 1200`，并用 `manualChunks` 将三方库拆分为 `vendor-react` / `vendor-charts`(recharts+d3) / `vendor-xlsx` / `vendor`。
- **效果**：主包从约 **851KB 降至 115KB**，各 vendor 包均 < 331KB，构建无任何体积告警；浏览器可按 vendor 维度分别缓存，命中率提升。
