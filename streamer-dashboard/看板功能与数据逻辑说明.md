# 线下主播看板 · 功能按键与数据逻辑说明

> 适用版本：当前线上包（dist `index-Dvts-9Ic.js`）
> 适用范围：主播数据、线下主播管理、运营数据看板、数据自动同步、线下主播赛事管理 五大模块
> 服务端口：后端 `8787`（Express，静态托管 dist + 提供 `/api/*`）

---

## 二、数据关联逻辑

### 1. 数据源与流向
```
B站后台（人工/Playwright）
   │  server/fetcher.js（fetchData / fetchDataByDate）
   ▼
server/data/today.json、yesterday.json        ← 按日抓取产物
   │  mergeRecords 合并
   ▼
server/data/latest.json                        ← 主数据集（权威）
   │  writeDataset 同步镜像
   ├─► public/streamer_data.json
   └─► dist/streamer_data.json                 ← 前端运行时读取（Express 静态托管）
   
server/data/roster.json                        ← 名册（权威）：线下/在职/赛道/自定义字段
   │  GET/POST /api/roster
   ▼
前端 useStreamerData() 加载并合并
```

### 2. 字段映射与合并（useStreamerData）
- **主记录 `records`（dailyRecords）**：每行来自 `streamer_data.json` 的原始 B站字段（`主播昵称/房间号/运营经纪人/总流水（元）/大航海人数/统计时间…`），经 `cleanRecord` 统一清洗（文本去空、数值解析、从「统计时间」提取 `统计日期/统计开始日期/统计结束日期`）。
- **名册增强字段**（来自 `roster.json`，按 `房间号` 关联）：
  - `是否线下主播` = `offlineRooms.includes(房间号)`
  - `在职状态 / 离职原因 / 离职日期` = `status[房间号]`
  - `开播日期 / 保底金额` = `extra[房间号]`
  - `赛道`（挑战赛用）= `tracks[房间号]`
- **主播维度 `streamers`**：将 `dailyRecords` 按 `房间号` 去重，仅保留「统计结束日期」最新的一条（区间快照优先），供线下主播管理等「一行一主播」场景使用。
- **挑战赛计算 `computeChallenge(records, {startDate,endDate,tracks,overrideWeek})`**：
  - 先过滤 `是否线下主播===true 且 在职状态!=='离职'`（离职自动剔除）；
  - 按自然周拆分；`overrideWeek`（2026-08-03~08-09）以 `roster.tracks` 为赛道权威；
  - 输出每周 `list`：`排名/赛道/晋级状态/是否获奖/是否达标/总流水`，及周级 `达标人数/总流水`。

### 3. 持久化分层
| 数据 | 存储位置 | 读写方 | 备注 |
|------|----------|--------|------|
| 抓取的每日流水明细 | `server/data/latest.json` + `public`/`dist/streamer_data.json` | 服务端写 / 前端只读 | 权威，分享链接可看 |
| 线下名册 / 在职状态 / 赛道 / 开播日期 / 保底金额 | `server/data/roster.json` | `GET/POST /api/roster`（需管理员口令） | 权威，刷新/换设备仍生效 |
| 运营经纪人 KPI 目标值 | `localStorage['agent_kpi_map_v2']` | 浏览器本地 | 仅本机，不上服务端 |
| 管理员口令 | `localStorage['sync_admin_token']` | 本地输入 | 写操作鉴权用 |
| 服务地址覆盖 | `localStorage['sync_api_base']` | 本地输入 | 断连时手动填 |
| 数据集离线兜底 | `localStorage['streamer_dashboard_data']` 等 | 前端写入 | 服务端不可达时回退；配额超限静默跳过 |
| 赛事活动列表（添加/删除） | `localStorage['challenge_events']` + `challenge_active_event` | 本地 | 仅本机，非服务端 |

### 4. 联动刷新逻辑
- **抓取成功**（`/api/fetch`、`/api/fetch-date`、`/api/catchup`）→ 服务端写 `latest.json` 并同步 `streamer_data.json`/`dist` → 前端调用 `onSync()` 重新拉取 `./streamer_data.json?t=时间戳`（带时间戳防缓存）。
- **名册变更**（`addOfflineRoom`/`setStreamerStatus`/`updateExtra`/`batchAddOfflineRooms` 等）→ 本地 state 更新 + `POST /api/roster` 写服务端；成功后用返回值刷新 `roster` state。**服务端为权威源，刷新页面后以服务端为准**。
- **导入Excel**（`/api/import`）→ 服务端**完整替换** `latest.json`（清空旧数据）→ `onSync()` 重载。
- **SyncPage 状态区** 每 15 秒自动 `GET /api/status` 轮询（登录态、上次抓取时间、漏跑情况）。

## 三、显示逻辑

### 1. 指标卡 / 图表数据来源
| 页面 | 展示项 | 数据来源 | 更新规则 |
|------|--------|----------|----------|
| 主播数据 | 总流水（区间）/ 本月有流水主播 / 本月总流水 | `aggregateByRoom` 按区间聚合 `records`，数值求和、粉丝数取最大 | 随区间/搜索/排序即时重算 |
| 线下主播管理 | 线下总数 / 在职 / 离职 | 来自 `streamers`（线下子集）统计 | 随名册与在职状态即时变 |
| 线下主播管理 | 保底金额汇总 / 当月开播 / 当月离职 | 线下子集按 `开播日期`/`离职日期` 取当月 | 随字段编辑即时变 |
| 运营看板 | 经纪人总流水占比（饼图） | 线下 `records` 按 `运营经纪人` 聚合 `总流水（元）` | 随区间/搜索即时重算 |
| 运营看板 | 本月 KPI 进度 | 当月全量+线下流水 vs `agent_kpi_map_v2` 目标 | KPI 输入即存本地并即时算 |
| 赛事管理 | 累计流水 / 达标人次 / 统计周数 | `computeChallenge` 各周 `总流水/达标人数` 求和 | 随名册/赛道/数据即时变 |
| 赛事管理 | 本周排位赛巅峰榜 TOP3 | 当前自然周内 `赛道==='排位赛' 且 总流水≥2000` 取前三 | **无人≥2000 时整块隐藏** |
| 同步服务 | B站登录态 / 上次抓取 / 最近结果 | `GET /api/status` | 每 15s 轮询 + 操作后刷新 |

### 2. 列表 / 表格显示规则
- **主播数据表**：按房间聚合后过滤（仅留有流水主播），分页 20/页，列可排序。
- **线下主播管理表**：`streamers` 一行一主播；离职行才显示「离职原因 / 离职日期」输入；保底金额有值时输入框标红强调。
- **运营看板表**：按经纪人聚合，可展开看 TOP3 主播；KPI 卡显示双进度条（线上线下总流水 / 线下流水），达标其一即标「已完成」。
- **赛事周明细表**：每周一条可展开；列含 排名/赛道/周流水/晋级状态/奖励资格；赛道筛选会改变名次（赛道内部排名）。

### 3. 状态标签配色
- **赛道徽章**：排位赛=金橙渐变高亮，晋级赛=品牌蓝。
- **晋级状态徽章**：含 `TOP`=金、含`晋级`=绿、含`排位落榜`=橙、含`冲刺`=蓝、其余=红。
- **在职状态**：在职=绿底，离职=灰底。
- **赛事周标**：达标人数 / 周流水=红底标签。

## 四、按键使用说明

### A. 数据同步类（SyncPage）
1. **导入Excel（顶栏）/ 同步数据（顶栏）**
   - 步骤：① 在 SyncPage 顶部输入**管理员口令**（见 `server/config.json` 的 `adminToken`）；② 点顶栏【导入Excel】选 B站导出 xlsx，或【同步数据】刷新。
   - 注意：未输口令会被拒绝（401）；导入为**整库替换**，旧数据不保留；分享链接无口令，仅可查看。

2. **扫码登录B站 → 我已完成登录**
   - 步骤：点【扫码登录B站】（本机弹浏览器）→ B站APP 扫码 → 点【我已完成登录】校验。
   - 注意：登录态存本机，定时任务自动复用；改版导致登录失效时重做即可。

3. **立即抓取【今日】/【昨日】**
   - 步骤：确认服务「运行中」→ 点对应按钮。
   - 结果：服务端 Playwright 打开 B站后台导出「按日汇总」→ 合并入 `latest.json` → 看板自动重载；结果在按钮下方绿/红提示。

4. **补抓指定日期**
   - 步骤：选日期（限近 7 天窗口）→【补抓指定日期】。
   - 注意：仅覆盖该日记录（按 `房间号::日期` 合并），不影响其他日期；超出 7 天需手动用 B站后台 Excel 导入。

5. **立即检查补跑 / 定时设置**
   - 步骤：【立即检查补跑】手动回溯错过任务；【定时设置】改 Cron（默认每 20 分钟抓今日、13:00 抓昨日）→【保存】。
   - 注意：服务停机后重启会自动补抓一次；运行中每 10 分钟自查。

6. **仅清空本地记录 / 清空全部数据**
   - 步骤：点按钮 → 弹确认框 →【确认】。
   - 区别：仅清空本地=清浏览器缓存，保留服务端名册与数据集；清空全部=服务端+本地全清（含线下标记/KPI），**不可恢复**，登录态保留。

### B. 线下主播管理类（StreamersList）
7. **添加 / 导入Excel房间号 / 粘贴房间号**
   - 步骤：输入房间号或选文件/粘贴（逗号空格换行分隔）→ 确认。
   - 注意：写入服务端 `roster.offlineRooms`（权威），刷新仍以服务端为准。

8. **在职状态下拉 / 离职原因 / 离职日期**
   - 步骤：选「离职」→ 填原因与日期（或留空）→ 自动写服务端。
   - 注意：离职后该主播在赛事挑战赛统计中**自动被剔除**（下一周起生效）；离职日期按你的要求此前留空、需手动补填。

9. **开播日期 / 保底金额**
   - 步骤：直接在行内编辑 → 即时写服务端 `roster.extra`。
   - 注意：保底金额有值时输入框变红提醒，汇总卡据此计算「在职主播保底金额汇总」。

10. **移除（线下行）**
    - 步骤：点【移除】→ 从线下名册删除（仍保留其历史流水数据）。

### C. 赛事管理类（ChallengePage）
11. **赛道筛选（全部/晋级赛/排位赛）**
    - 步骤：点对应标签。
    - 结果：各周明细表只显示所选赛道，且**名次按该赛道内部流水重排**（非全局混合名次）；「该赛道暂无数据」时给出空态提示。

12. **本周排位赛巅峰榜 TOP3**
    - 显示：当前自然周内排位赛且周流水≥2000 的主播前三，标题旁标注统计日期范围（如 `2026-08-03 至 2026-08-09`）。
    - 隐藏：当周排位赛**无人≥2000 时整块不显示**（不占位）。

13. **周卡片展开/收起、赛事重命名/删除、添加活动**
    - 步骤：点周 Header 展开明细；详情页可改名、删除当前赛事；首页【添加活动】新建。
    - 注意：赛事活动列表存 localStorage（本机），赛道/在职状态存服务端；活动删除至少保留 1 个。

### D. 通用
14. **同步数据（顶栏）vs 刷新状态（SyncPage）**
    - 顶栏【同步数据】= 重新拉取流水数据集；SyncPage【刷新状态】= 重新检测服务/登录态。两者不冲突，可分别使用。
15. **版本徽标**
    - 金色且带 ⚠ = 检测到前端包与服务端版本不一致，建议重新构建/部署后强刷（Ctrl+Shift+R）。
