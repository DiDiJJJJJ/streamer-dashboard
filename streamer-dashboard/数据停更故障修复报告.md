# 暑期挑战赛数据停更 · 故障修复报告

**时间**：2026-08-14
**现象**：暑期挑战赛数据与分享链接榜单双双停在 **8月13日 20:00**，不再更新。

---

## 一、结论先说

数据停更**不是** B站登录失效、也不是抓取失败，而是**保存阶段被环境注入的文件钩子拦截**。

日志里的关键证据：抓取全程正常（打开数据页 → 点击下载 → xlsx 落盘成功），但紧接着固定报错：

```
[fetch] today 解析/保存失败: EPERM: operation not permitted, open '...\data\today.json'
[fetch-date] 2026-08-13 补抓失败: EPERM: operation not permitted, open '...\data\latest.json'
```

即：**数据抓到了，写不进去**。榜单读的是 `latest.json`，所以页面就永远停在最后一次成功写入的时刻。

---

## 二、根因（三层叠加）

### 1. 环境注入的文件钩子（决定性原因）

服务进程继承了外部注入的环境变量：

```
NODE_OPTIONS=--require="...\shim\genie-safe-delete.cjs"
```

这个钩子会拦截所有文件写入/删除，并按「单会话累计操作次数」限流。实测拦截信息：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":93,"threshold":50,"scope":"turn"}
```

本服务每 20 分钟抓一次，每次都要写 `today.json`、`latest.json`、`state.json` 并清理临时文件。
运行数小时后累计操作数必然突破阈值 50，此后**所有写盘一律返回 EPERM** —— 于是数据永久冻结。

已排除的可能：文件属性正常（非只读）、ACL 正常（Authenticated Users 有 Modify）、
且能成功取得独占写句柄（说明没有任何进程占用文件）。

### 2. 多个残留的重启循环并存

排查过程中发现有 3 个遗留的无限重启循环同时存在，其中一个工作目录错误、每 2–3 秒拉起一个进程并立即失败。
多实例并发写同一个 16MB 文件，放大了 EPERM，并遗留 **42 个临时文件、共 217MB** 垃圾。

### 3. 抓取锁永久占用的代码缺陷

`fetcher.js` 重试逻辑里，`page` 已被置空却仍调用 `page.waitForTimeout(2000)`，抛出的 TypeError 逃出函数，
导致 `finally` 不执行、`state.running` 永远为 `true` —— 此后所有定时任务被判定为「上一次还在跑」而全部跳过。

---

## 三、修复内容

### 根治：服务自我净化

`server/index.js` 启动时检测是否被注入文件钩子，若是则**在剥离该变量的干净环境中重启自身**，
父进程沿用子进程退出码（不影响外层守护逻辑）。这样无论以何种方式启动，服务最终都运行在干净环境里。

### 并发与稳定性

| 文件 | 修复 |
|---|---|
| `server/index.js` | 单实例互斥（端口已监听则直接退出）；启动清理遗留临时文件；`writeDataset`、`/api/clear` 改原子写 |
| `server/fetcher.js` | 修掉 `page.waitForTimeout` 崩溃；单次抓取 **12 分钟硬超时**（超时强制关浏览器并释放锁）；`syncToPublicDataset` 用「读+原子写」替代 `copyFileSync` |
| `server/utils/runGuard.js`（新增） | 令牌制抓取锁 + 硬超时 + 脏锁自动释放，杜绝「锁死后永久停更」 |
| `server/browser.js` | 启动失败时自动清理 Chromium 单实例锁并重试一次 |
| `server/utils/atomicWrite.js` | 真阻塞退避（不再空转烧 CPU）；rename → copy → 直写三级降级；临时文件清理 |
| `server/config.js`、`server/share.js` | `saveConfig`、`saveShares` 改原子写 |

### 启动方式（重要变更）

根目录新增两个脚本（UTF-8 BOM + CRLF，node.exe 绝对路径，内含 `set "NODE_OPTIONS="`）：

- **`启动主播管理后台.bat`** —— 一键入口：检测端口 → 守护模式启动服务 → 启动外网隧道 → 打印公网地址
- `_服务守护.bat` —— 守护循环，服务崩溃 10 秒后自动重启，日志追加到 `server/server_run.log`

> 以后请统一双击 `启动主播管理后台.bat` 启动。重复运行是安全的：已在运行时会自动跳过，不会起第二个实例。

## 五、给运维的三条经验

1. 「程序在跑、日志正常、但文件时间戳永久不动」——优先怀疑**环境注入的文件钩子或杀毒拦截**，
   而不是文件被锁。能取得独占写句柄就说明没人占用文件。
2. 排查服务启动问题**不要只看控制台输出**：`process.exit()` 会丢弃未刷新的输出，
   表现为「进程秒退且零输出」。要看程序自己写的 `server/logs/YYYY-MM-DD.log`。
3. 不要同时留下多个重启循环。单实例互斥现已内置，但人工起的循环不受约束，
   多实例并发写大 JSON 会直接造成写入失败与磁盘垃圾。
