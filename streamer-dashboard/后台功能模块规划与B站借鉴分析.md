# 线下直播场地管理后台 — 功能模块补充与 B站 后台借鉴分析

> 面向对象：线下直播场地主管
> 现有数据基础：运营人员工作情况、场地总体运营状态、整体业务盘子分析、每位运营对应主播（线上+线下）的数据涨跌趋势。
> 目标：全盘梳理后台还需补充的功能模块与指标，并参考 B站 创作者/直播后台菜单结构优化看板分析能力。

---

## 一、B站 创作者 / 直播 / 公会 后台菜单结构梳理（可借鉴项）

### 1.1 创作中心（member.bilibili.com，UP 主视角）
- **首页 / 数据概览**
- **内容管理**
  - 稿件管理（视频）、专栏管理、音频管理、合集与列表
- **数据中心**
  - 视频数据（播放量、点赞、投币、收藏、弹幕、分享、完播率曲线）
  - 专栏数据、直播数据
  - 粉丝数据 / 用户画像（性别、地域、关注行业、游戏偏好、粉丝 vs 非粉丝占比）
  - 流量来源分析（推荐流 / 搜索 / 分区 / 个人主页 / 外部）
- **互动管理**：评论管理、弹幕管理、私信
- **收益中心 / 收入结算**：直播收益（金仓鼠，1000:1 兑换 RMB）、创作激励、充电计划、商务合作

### 1.2 直播中心（live.bilibili.com，主播视角）
- **我的直播间**
- **直播设置**（设备、推流、分区）
- **直播数据**（核心可借鉴维度）
  - 周期筛选：昨日 / 7 天 / 30 天 / 自定义
  - 指标：**直播时长、直播收益、最高人气值、弹幕数、新增关注数、用户平均观看时长**
  - 礼物分析：礼物收益、礼物类型 Top、礼物价值分布、**新增大航海分布**
  - 弹幕分析：弹幕数、弹幕人数、弹幕趋势、**弹幕热词 / 弹幕词云**
  - 观众画像：性别分布、地域、关注 UP 主偏好
  - 带货分析：商品信息、GMV
- **直播收益、大航海 / 粉丝勋章、直播回放**

### 1.3 公会中心（最接近"场地 / 经纪管理"的类比）
B站 的"公会 / 经纪"后台是多主播管理的直接参照，其菜单通常包含：**成员管理、成员业绩、收益分成、分级运营、异动与风控**。本场地的"运营人员—主播"管理结构与该模式高度同构，是菜单设计的最优参照。

### 1.4 可直接借鉴的数据分析维度
| 维度 | 看板含义 |
|------|----------|
| 最高人气值 / 用户平均观看时长 | 直播间"过程健康度"，先行于流水 |
| 弹幕数 / 弹幕人数 / 弹幕热词 | 互动质量与内容话题度 |
| 新增关注数 | 涨粉能力（主播生命周期关键指标）|
| 礼物结构 / 大航海占比 | 收益质量，而非仅看总额 |
| 直播时长 | 产能与投入度 |
| 7/30 天趋势 + 分区筛选 + 同环比 | 标准化复盘口径 |
| 粉丝画像 | 受众匹配与内容方向建议 |

## 二、当前系统能力盘点

### 已有（基于现有代码与数据）
- **主播数据页**：今日 / 昨日 流水、大航海人数、运营经纪人、房间号、主播昵称（含线上线下标记、在职/离职名册）。
- **KPI 完成进度**：线上线下总流水进度、KPI 输入框。
- **挑战赛分享链接**：海报生成、实时同步（SSE + no-store）。
- **名册（roster）**：运营—主播绑定、状态（在职/离职）、线下/线上区分。

### 明显缺口（场地主管视角）
1. **没有成本与利润**：只有"流水"，没有场地成本、人力成本、分成后净收入，无法判断"赚不赚钱"。
2. **没有互动/内容质量过程指标**：只有流水结果，缺人气、时长、弹幕、涨粉等先行指标，无法提前预警流水下滑。
3. **没有场地/直播间资源运营**：房间占用、坪效、排班全缺失。
4. **没有运营人效**：每位运营名下主播数、人均产出、流失率、饱和度未量化。
5. **没有主播分层与异动预警**：所有主播一视同仁，衰退期/高风险主播无法被自动识别。
6. **没有异常风控**：流水骤降、掉粉、违规、大航海流失无主动告警。
7. **没有对标基准**：缺同环比、运营间横向对比、分区/同类中位数。

## 三、建议新增模块（模块名 / 层级 / 核心指标 / 管理价值）

### 模块 1：场地运营
- **层级**：一级「场地运营」> 二级「直播间资源看板」「排班与占用率」
- **核心指标**：直播间总数 / 在用 / 空闲、占用率(%)、单间日均流水（坪效）、单间开播时长、设备/网络健康分
- **管理价值**：提升场地利用率与单位面积产出，识别闲置/低效房间，支撑排班与扩租决策
- **B站 借鉴**：直播中心 > 直播设置（设备/推流）、分区管理

### 模块 2：团队管理（运营人效）
- **层级**：一级「团队管理」> 二级「运营绩效看板」「主播-运营负载」
- **核心指标**：运营名下主播数、人均管理流水、主播流失率、新签主播数、人均产能、运营饱和度（负载上限）
- **管理价值**：识别高/低绩效运营，防止运营过载导致主播流失，优化人力配置与激励
- **B站 借鉴**：公会中心 > 成员管理 / 业绩

### 模块 3：主播分层与生命周期（增强现有"主播管理"）
- **层级**：一级「主播管理」> 二级「分层分级（S/A/B/C）」「生命周期与异动预警」（名册为现有基础）
- **核心指标**：在职/新增/流失、成长期/成熟期/衰退期分布、S/A/B/C 分层、流水环比、掉粉率、预警触达
- **管理价值**：精准投放运营资源，及时挽留衰退/高流失风险主播，量化"主播资产"健康度
- **B站 借鉴**：数据中心 > 粉丝数据 / 用户画像

### 模块 4：内容数据（当前全缺，过程指标）
- **层级**：一级「内容数据」> 二级「直播质量」「互动分析」「礼物结构」
- **核心指标**：人气峰值、人均观看时长、弹幕数/弹幕人数、弹幕热词、新增关注、开播时长、违规次数、大航海占比
- **管理价值**：流水是结果，互动/人气是先行指标；提前预警流水下滑，指导内容策略与培训
- **B站 借鉴**：直播中心 > 直播数据（最高人气/弹幕数/人均观看时长/新增关注）、礼物分析、弹幕分析、观众画像

### 模块 5：经营分析（成本利润）
- **层级**：一级「经营分析」> 二级「营收与成本结构」「利润与盈亏平衡」
- **核心指标**：总流水、平台分成后净收入、场地成本、人力成本、毛利率、单主播盈亏平衡、线上 vs 线下成本差
- **管理价值**：从"流水"走向"利润"，识别亏损主播/房间，支撑定价与分成谈判
- **B站 借鉴**：创作中心 > 收益中心（金仓鼠兑换、创作激励、充电）、收入结算

### 模块 6：目标激励与排行榜（增强现有 KPI）
- **层级**：一级「目标激励」> 二级「KPI 看板」（现有）「排行榜」「提成测算」
- **核心指标**：KPI 完成率、月度/周排名、增长榜、新秀榜、提成预估、达标率
- **管理价值**：透明化目标，激发运营与主播积极性，降低管理沟通成本
- **B站 借鉴**：直播中心 > 人气榜 / 大航海榜、数据总览

### 模块 7：风控中心（异常预警）
- **层级**：一级「风控中心」> 二级「异常监控」「违规记录」
- **核心指标**：流水异常波动、掉粉率、违规次数、大航海流失、直播中断/掉线
- **管理价值**：主动干预，降低经营与合规风险，把"事后对账"变成"事前预警"
- **B站 借鉴**：直播低俗擦边治理公告、粉丝勋章亲密度改版（运营动作参考）

### 模块 8：对标与基准（横向对比）
- **层级**：一级「风控中心 / 对标分析」> 二级「同环比」「运营对比」
- **核心指标**：环比/同比、同类主播中位数、运营间对比、分区基准达标率
- **管理价值**：客观评价表现，避免"只看绝对值"造成的误判
- **B站 借鉴**：数据中心 7/30 天趋势、分区筛选

## 四、建议的后台整体菜单树（融合方案）

见上方可视化菜单树。要点：**保留现有"数据概览 / 主播管理 / 目标激励"并增强**，新增"团队管理 / 场地运营 / 内容数据 / 经营分析 / 风控中心"五大模块，形成"人（团队+主播）—场（场地）—内容（过程）—钱（经营）—险（风控）"的完整闭环。

## 五、落地优先级

- **P0（复用现有数据，立刻可做）**：模块 2 运营人效、模块 3 主播分层与异动、模块 6 排行榜、模块 7 异常预警（基于流水波动/掉粉/离职）。
- **P1（需补充采集字段）**：模块 4 内容数据（扩展 fetcher 抓取开播时长/人气/弹幕/新增关注，来自 B站 直播数据页）、模块 5 成本利润（录入/对接成本）、模块 1 场地资源（房间排班占用数据）。
- **P2（沉淀后做）**：模块 8 对标基准（需足够历史与同类样本）。

## 六、数据需求清单（下一步建设依赖）

| 模块 | 需新增采集/录入字段 |
|------|---------------------|
| 内容数据 | 开播时长、最高人气、弹幕数、弹幕人数、新增关注、违规次数（来自 B站 直播数据导出，扩展现有 fetcher）|
| 经营分析 | 单主播分成比例、场地租金/折旧、运营人力成本、设备成本 |
| 场地运营 | 直播间清单、排班表、占用记录、设备/网络状态 |
| 团队管理 | 运营-主播绑定（已有）、运营编制与负载上限 |
| 主播分层 | 分层规则（流水/涨粉阈值）、生命周期阶段打标 |

> 说明：现有 fetcher 已能抓"总流水 / 大航海人数 / 运营经纪人"，建议在同一 B站 直播数据页一并抓取"开播时长 / 人气 / 弹幕 / 新增关注"，即可低成本解锁模块 4 的全部过程指标。
